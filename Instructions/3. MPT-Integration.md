# MPT Integration — Using MoneyPrinterTurbo as the Orchestration Layer

> Plan to use MoneyPrinterTurbo (MPT) with the video generation tools laid out in [2. TV-show-episode-recreation.md](file:///c:/Projects/moneyprinterturbo/storage/Instructions/2.%20TV-show-episode-recreation.md).

**Core principle:** Use MPT as the **orchestration/editing layer**, not as the thing responsible for maintaining your TV-show characters.

The current repository supports: custom scripts, AI-generated scripts, multiple AI-video providers, local/uploaded footage, voiceover, subtitles, music, API/CLI workflows, and batch generation. It already integrates with Seedance, MiniMax, Wan, MuAPI, and other providers.

## What MPT Already Gives You

MPT handles much of the infrastructure you'd otherwise build yourself:

```
Input → script → footage → voice → subtitles → music → final video
```

It exposes both a **WebUI** and **API/CLI** workflows.

### Key capabilities for this use case

- **Custom scripts** — you don't want MPT deciding what happens in the episode; your episode-analysis pipeline produces the script and shot plan, then feeds it into MPT.
- **AI footage from multiple providers** — Seedance, MiniMax, Wan, MuAPI and others are already integrated.
- **API service** (`localhost:8080`) and **CLI mode** — suitable for automated pipelines (no UI required).
- **Batch generation** — important for producing many episodes.

## The Most Important Modification

### Problem: MPT's default workflow

MPT's normal workflow is:

```
script sentence → search/generate footage → put footage underneath sentence
```

This is perfect for *"5 things you didn't know about Japan"* but **not ideal for TV recaps**.

### Required: Shot-based workflow

```yaml
SHOT 1:
  characters: [A, B]
  location:   house
  action:     A confronts B
  camera:     close-up
  duration:   5 sec
  references: [characters/A.png, characters/B.png, locations/house.png]
  → VIDEO CLIP

SHOT 2:
  characters: [A]
  location:   street
  action:     A walks away
  camera:     tracking
  duration:   4 sec
  references: [characters/A.png, locations/street.png]
  → VIDEO CLIP

SHOT 3:
  ...
```

Then MPT assembles the resulting clips.

## Character Consistency — The Part MPT Doesn't Solve

This is the key challenge MPT doesn't address. Your shot generator must know which characters appear in each shot and retrieve their reference images:

```json
{
  "shot": 4,
  "characters": ["alice", "bob"],
  "location": "restaurant",
  "action": "Alice discovers Bob's secret",
  "camera": "medium two-shot",
  "duration": 5
}
```

Then retrieve:

```
characters/alice/reference.png
characters/bob/reference.png
locations/restaurant/reference.png
```

…and send those to the video model where supported.

> **Keep this logic outside MPT's existing generic script-to-video pipeline.**

## Audio Strategy — Narration Over Silent Clips

> **Don't generate dialogue inside every video clip.**

### Recommended approach

| Layer        | What it does                                    |
| ------------ | ----------------------------------------------- |
| **AI Video** | Generate **silent** cinematic clips             |
| **Voice**    | Generate one continuous narration track         |
| **MPT**      | Synchronize: video clips + narration + music + subtitles → final MP4 |

### Why this is better

You avoid:

- Lip-sync errors
- Inconsistent voices
- Dialogue getting cut off
- Video model mispronouncing names
- Audio changing between shots

Character dialogue can be added later as a refinement.

### Example LLM Output

```json
{
  "duration": 60,
  "narration": "Walter thinks everything is under control. But Jesse has already made a dangerous decision...",
  "shots": [
    {
      "duration": 5,
      "characters": ["walter", "jesse"],
      "location": "desert",
      "prompt": "Walter confronts Jesse beside the RV..."
    },
    {
      "duration": 4,
      "characters": ["walter"],
      "location": "rv",
      "prompt": "Walter examines the chemical equipment..."
    },
    {
      "duration": 6,
      "characters": ["jesse"],
      "location": "desert",
      "prompt": "Jesse nervously watches Walter..."
    }
  ]
}
```

Custom code calls the video provider → `shot_001.mp4`, `shot_002.mp4`, `shot_003.mp4` → hands them to MPT's assembly pipeline.

## Implementation Strategy

### Phase 1: Start with what MPT already supports

> After looking at the current MPT repository, **don't immediately bolt Kling/Veo directly onto it.**

First, use the video providers MPT already supports — particularly **Seedance** — and get the core pipeline working:

```
episode → LLM summary → 60-sec script → shot planner
   → reference images → Seedance/MPT video generation
   → MPT voice/subtitle/music/edit → MP4
```

Once that works, adding another generator becomes an **adapter** rather than a rewrite.

### Phase 2: Approach

- **Do NOT** fork MPT and rewrite everything.
- Build a relatively thin **"TV Recap Engine"** layer on top of / alongside MPT.
- Let MPT continue doing what it's already good at: media generation/assembly, voice, subtitles, music, and final rendering.

### Next Step

Go through the MPT repository structure and identify the **exact Python files/functions** to modify, then design the new `tv_recap` module around the existing code rather than guessing at its architecture.
