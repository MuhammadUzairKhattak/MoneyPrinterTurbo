What Needs to Be Built (The Gap)
The instructions identify these capabilities that don't exist in MPT:

🔴 1. Episode Analysis (LLM-powered)
Goal: Take episode content → produce structured scene-by-scene script

Current gap: MPT's llm.generate_script() generates generic video scripts from a subject line. It doesn't:

Parse episode plots into narrative arcs
Output structured shot-by-shot JSON
Handle character extraction or scene decomposition
New module: app/tv_recap/episode_analyzer.py

🔴 2. Character Consistency Manager
Goal: Maintain a character bible per show with reference images

Current gap: MPT has no concept of "characters" — it works with generic search terms or AI prompts. There's no:

Character definition storage
Reference image management
Injection of character references into video generation prompts
New module: app/tv_recap/character_manager.py

🔴 3. Scene/Shot Planner
Goal: Convert a 60-sec narrative into a structured shot list with character, location, camera, and duration per shot

Current gap: MPT's generate_terms() produces flat search keywords. It doesn't:

Plan shots with specific characters, locations, camera angles
Calculate durations to fit a target total
Map characters to reference images per shot
New module: app/tv_recap/scene_planner.py

🔴 4. Reference-Aware Shot Generator
Goal: Generate video clips that include character/location reference images in the prompt

Current gap: MPT's video generation sources (Seedance, WaveSpeed, etc.) accept text prompts only. They don't:

Attach reference images to generation requests
Use character sheets for consistency
Support the kind of reference-based workflows described for Kling/Veo
New module: app/tv_recap/shot_generator.py

🔴 5. TV Recap Assembler (Modified Pipeline)
Goal: Assemble pre-generated clips (not search results) through MPT's voice + subtitle + music + FFmpeg pipeline

Current gap: MPT's
task.py
 assumes material comes from search or AI generation. The TV recap workflow needs to:

Accept pre-generated clip files as input
Skip the generate_terms() + download_videos() stages
Go straight to voice → subtitle → music → assembly
New module: app/tv_recap/video_assembler.py

🟡 6. Kling / Veo Adapters (New Provider Integrations)
Goal: Add Kling 3.0 and Veo 3.1 as video generation backends

Current gap: MPT supports Seedance, MiniMax, WaveSpeed, MuAPI, OFox, LoomLoom — but not Kling or Veo. The instruction docs recommend:

Kling 3.0 as the primary workhorse (multi-shot, reference consistency)
Veo 3.1 for premium shots (native audio generation)
IMPORTANT

The instructions wisely advise starting with Seedance (already integrated) before adding Kling/Veo. This is the correct Phase 1 approach.

Generate narration audio via voice.tts()

Key Risks & Decisions
🔶 Character Consistency Without Reference Images
Phase 1 relies entirely on prompt engineering. Generated characters will look different across shots. Mitigation: Use very detailed, consistent character descriptions in every prompt.

🔶 Seedance Limitations for Multi-Character Scenes
MPT's Seedance integration generates from text prompts only. Multi-character scenes with specific interactions may produce inconsistent or low-quality results. Mitigation: Use simpler compositions (one character per shot + narrator) initially.

🔶 Legal Risk for TV Show Content
The instructions correctly flag this. Decision needed:

Option A: Use original characters inspired by archetypes (safe, publishable)
Option B: Recreate actual characters (risky, educational/fair-use only)
🔶 Episode Source Material
How does the episode content get into the system?

Option A: User writes/pastes a summary
Option B: User provides a transcript
Option C: LLM summarizes from Wikipedia/fan wiki
Option D: Audio/video analysis of the actual episode
🔶 Cost Per Episode
Each episode requires 8–15 AI video generation calls. At current API pricing:

Seedance: ~$0.05–0.15 per clip → ~$0.40–2.25 per episode
Kling/Veo (future): potentially higher
